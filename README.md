# Noire · 美股自动交易系统

> 原名 Excaliber，2026-10-15 改名为 Noire（法语“黑色”，取 “in the black” 盈利之意），以和 ChatGPT 的 Excalibur 区分。

目标路线：**回测 → 模拟盘 → 小资金实盘 → 加入 AI**。当前处于第 3 阶段（模拟盘）；实盘模式已写好、默认关闭，计划 11 月小额尝试（见第十五节）。

## 一、第一次运行（Windows）

1. 安装 Python 3.10 以上版本：https://www.python.org/downloads/ （安装时勾选 **Add Python to PATH**）
2. 打开命令提示符（Win+R → 输入 `cmd`），然后运行：
   ```
   cd /d D:\claude\Noire
   pip install -r requirements.txt
   python backtest.py
   ```
3. 结果会打印在屏幕上，图表和表格保存在 `reports\` 文件夹。

以后直接双击 `run_backtest.bat` 就能运行。

## 二、文件说明

| 文件 | 作用 |
|---|---|
| `config.py` | 所有参数：股票、日期、均线天数、手续费、止损 |
| `data.py` | 从 Yahoo Finance 下载日线数据，缓存到 `data\` |
| `strategy.py` | 策略（当前是 50/200 日双均线），想换策略就改这里 |
| `backtest.py` | 回测引擎：扣成本、次日开盘成交、止损、和买入持有对比 |

## 三、怎么看结果

- **年化收益**：每年平均赚多少
- **夏普比率**：每承担一份风险能换来多少收益，大于 1 算不错，小于 0.5 一般
- **最大回撤**：从最高点最多跌了多少，这个数决定你拿不拿得住
- **一定要和“买入持有”比**：跑不赢一直拿着 SPY 不动的策略，就没必要做

双均线策略在大牛市里通常跑不赢买入持有。它的价值在于大跌时（比如 2008、2022 年）把回撤压小，这是一个学习用的基准，不是赚钱秘籍。

## 八、工程加固（2026-10-15，借鉴 ChatGPT 版的做法）

- **订单唯一编号 + 台账**（`ledger.py`，`logs\order_ledger.jsonl`）：每笔订单编号 `noire-rot-日期-标的-方向`（手动单 `noire-man-...`）。

  **每天 17:00 换仓前自动先跑一遍（`preflight.py`），任何一项不通过当天就不交易并报警。**
- **git**：`setup_phase2.bat` 建立本地仓库；每天换仓前自动提交一次。密钥、数据、日志不进 git。
- **成绩单**（`scoreboard.py`）：每天 17:00 在 `equity_history.csv` 记一行净值，和同期 SPY 比较 → `reports\scoreboard.txt`。
  其他系统按同样格式（`date,equity` 两列的 CSV）放进 `scoreboard\` 文件夹就会一起比较。
- 修复：账户第一天券商没有“昨日净值”时，“今日盈亏”改用当天首次记录的净值计算。

## 九、有限次数自动重试（2026-10-15，借鉴 ChatGPT 版讨论）

`paper_job.py`：计划任务在 17:00、17:30、18:00 各运行一次。
- 今天已成功 → 直接跳过；另一次运行未结束（运行锁 <25 分钟）→ 跳过。
- 每次都先跑安全自检，换仓程序内部再核实台账、检查 STOP；订单编号固定，重试不会重复下单。
- 前两次失败只记日志；第 3 次仍失败才报警推送。
- 17:00 换仓的输出和 `reports\paper_status.txt` 增加“实际杠杆 / 距追缴保证金”。

## 十一、A+ 稳健版上线（2026-10-15，用户选定）

实盘规则（`aplus.py`，参数在 `config.py`；与 `research\research_v2.py` 的“A+ 稳健版”相同）：
1. **分 4 批换仓**：资金分 4 份，换仓日分别是每月最后一个交易日、以及它之前第 5、10、15 个交易日（用 Alpaca 交易日历算）。
   每批在自己的换仓日收盘后按 1/3/6/12 个月收益均值选前 2 名，持有到它的下一个换仓日。
2. **波动小的多买**：每批选中的两只按近 63 天日波动的倒数分配；分数 ≤0 的那一份换成 SHY。
3. **杠杆** = 30% ÷ 4 批合并后组合近 63 天的年化波动，限制在 1~2 倍；**SPY 收盘低于 200 日均线时最多 1 倍**。
4. **不借钱买现金**：杠杆只加在风险资产上，SHY 只用自有资金买。
5. 其余不变：收盘后提交市价单、次日开盘成交；相差不到总资产 5% 不动；单日亏 5% 只卖不买；STOP；订单唯一编号；Reg T 购买力上限。

历史模拟（2000 至今，5 种分批方式平均）：年化约 13.1%（按 Alpaca 真实借钱利息约 12.3%）、平均最大回撤约 -39%（最坏 -42%）；研究里核对过 738 个交易日的目标仓位，实盘程序和回测完全相同。（10-16 修正：之前写的 13.5% / -36% 只覆盖了 2 种分批方式，偏乐观。）
`paper_status.txt` 和换仓输出会列出 4 批各自的信号、合并后的权重、杠杆是怎么算出来的。

## 十三、第二条腿 + 对账工具（2026-10-16 用户同意启用；10-16 晚装上，10-19 周一 17:00 起生效）

**第二条腿：RSI(2) 超跌反弹**（`dipbuy.py`，参数在 `config.py` 的 `DIP_*`；规则和 `research\research_v3.py` 的 S1 相同，参数来自公开文献，没有调）：
1. **买**：SPY 收盘在 200 日均线上方（大趋势向上），而且 2 日 RSI < 10（最近两天跌得很急）。
2. **卖**：SPY 收盘高于 5 日均线（反弹了）。2000 年以来每年约 7~8 次，每次平均拿 3~4 天（最长 11 天），约 10% 的交易日有仓位。
3. **只用 A+ 没用完的额度**：第二条腿最多 = min(1 倍, 2 倍 − A+ 当天的风险资产仓位)，**总仓位永远不超过 2 倍**；
   A+ 已经用满 2 倍时就不加（历史上持有信号的日子里约一半是这样）。要用钱时先用 SHY 那部分自有资金，不够才借。
4. 和 A+ 在同一次 17:00 运行里算、一起下单（收盘出信号 → 次日开盘成交）；持仓状态每天由历史价格从头推算，不需要额外的状态文件。
5. 单日亏损超过 5% 那天照样只卖不买（第二条腿的买入会推迟到第二天，研究里没算这一点）。
6. 关掉：把 `config.py` 里的 `DIP_ENABLED` 改成 `False`（A+ 稳健版照常运行）。

上线前的核对（2026-10-16）：实盘程序和研究的买卖信号在 1993 年以来 8485 个交易日上完全一致；
2006 年以来第二条腿持有的 570 天里，实盘算出的“剩余额度”和研究完全相同（误差 < 1e-14）。
`paper_status.txt` 和换仓输出会多一行“第二条腿：未持有 / 持有中（哪天触发、用了多少额度）/ 卖出信号”；
`logs\targets.csv` 单独记录第二条腿占的仓位（`dip` 列），日报和周报据此分开记账。

**对账工具**：
- `fills.py`：`monitor.py` 每小时把本系统订单的实际成交价记到 `logs\fills.csv`（同一笔只记一次）。
- `tracking.py`：每天比较“账户实际赚的”和“完全按目标仓位、按开盘价成交应该赚的”，并算成交价比开盘价吃亏多少
  → `reports\tracking.txt`；第二条腿的贡献单独列出。只读，不连券商。

## 十四、程序加固 + 研究 v4（2026-10-16 凌晨，和第二条腿一起上线）

用户要求“再仔细钻研有什么可以改或优化的地方”。逐个文件检查后修了 6 处（都有新测试，共 56 项）：
1. **自检里的“定时炸弹”**：测试用的假行情以前是“随机走势画到今天”，每过一天就变一点。模拟发现从 **2027-02-12** 起测试会失败，
   而自检失败会让当天停止自动交易。现在假行情是固定的（每天形状完全一样），2030 年底以前每个工作日都验证过。
2. **券商明确拒单不再当成“结果不明”**（`ledger.py`）：例如购买力不足（HTTP 403）以前会触发“结果未知”警报并停下当晚其余订单；
   现在记为 REJECTED、报警说明原因、其余订单照常，第二天按最新仓位重新计算。超时、断线等真正不确定的情况仍然停下核实。
3. **买单不超过券商“现在”的购买力**（`paper_rotation.py`）：Alpaca 规定还没成交的卖单不算进购买力；超出的部分自动缩小，等卖单成交后下一次运行再补。
4. **卖出股数不超过持有股数**：券商市值和本地收盘价差得多时（例如盘后大涨），以前可能算出比持有更多的卖出股数 → 意外做空。现在封顶。
5. **坏数据保护**：任何一只最新价格缺失、≤0，或一天涨跌超过 25%（这几只 ETF 历史上从来没有过，多半是数据出错）→ 当天不交易；
   Yahoo 限流时同一次运行里自动再试两次（等 20 秒、60 秒）；新下载的数据明显不完整就不覆盖本地缓存；行情不是最新的会在状态和警报里提醒。
6. **其他**：监控以 `logs\paper_job_state.json` 判断上次换仓成败（重试成功不再误报“出错”）；成交记录“部分成交 + 全部成交”只算一次；
   休市日不记成绩单；重复编号被拒时向券商查一下并记进台账（避免误报“台账没有记录”）；
   空跑（不带 `--live`）的结果写到 `reports\paper_status_dryrun.txt`，不再覆盖正式的 `paper_status.txt`（日报、周报读的是正式的）。

**研究 v4**（`research\research_v4.py` → `research\report_v4.md`，结论在 `research\notes_v4.md`）：
试了 5 个有道理的改法（第二条腿扩展到 QQQ/IWM、第二条腿收盘成交、避险资产换 BIL、趋势开关加两种缓冲），**全部没达到事先定的标准，策略不改**。
另外：实盘执行规则比研究的理想执行每年只少约 0.1~0.2 个点；交易成本是最大的未知数（0.10% → 0.03% 每年多约 1.5 个点，等真实成交数据）；
压力测试：满仓 1.96 倍时单日暴跌 20% 账户会亏约 39%，要单日跌约 30% 才会被追缴保证金。

**研究 v5**（10-16 下午，`research\research_v5.py` → `research\report_v5.md`；数据：`research\fetch_long.bat` 下载标普 500 指数 1927 年起）：
- 第二条腿在 1950–1992 年（以前没用过的数据）勉强通过（每笔 +0.06%、胜率 62%），但 1960 年代是亏的 → 效应强弱随年代变化。
- 杠杆规则在历次大跌里只比 1 倍多跌约 1~10 个点，远好于固定 2 倍；1987-10-19 那天趋势开关已降到 1 倍（有运气成分）；没有一次被追缴。
- 极端风险：1929 年那样从 200 日线上方直接崩盘时，第二条腿会把总仓位补回 2 倍（近似：单日约 -26%）；试过“趋势开关也管第二条腿”，
  每年少约 0.8 点、平均回撤反而变大 → 不改，作为已知风险接受。
- `research\expectations.md` 已按“A+ 稳健版 + 第二条腿”重算（每年约 13.6%，回撤超过约 39% 算超出历史）。

## 十五、实盘模式（真钱；2026-10-18 写好，默认关闭）

用户 10-17 决定 11 月用小额真钱试。**模拟盘照常每天运行（当对照组）**；实盘是另一套任务和记录，两边互不影响。

### 1. 三道闸：三条都满足才会用真钱下单
1. `config.py` 里 `LIVE_ENABLED = True`
2. **你本人**双击 `enable_live.bat`，输入 `YES`（会在 `live\` 里留下 `LIVE_ENABLED` 文件）——Claude 不会替你做
3. `config.py` 里 `LIVE_MAX_CAPITAL`（实盘最多管理多少美元）大于 0

任何一条没满足：自动换仓只写一行“实盘自动交易没有打开（原因）”，不跑自检、不下单。
只看不下单的脚本（空跑、查状态、监控）只需要实盘密钥，用的是“只读连接”——程序层面就不允许下新单。

### 2. 打开以后的限制（写死在代码里，有测试）
- **只管理 `LIVE_MAX_CAPITAL` 美元**：账户里多出来的钱不动。赚了钱、超过上限的部分会留成现金；想让它继续投入，就把上限调高。
- **杠杆不超过 `LIVE_MAX_LEVERAGE`**：1.0 = 不借钱；1.5；2.0 = 和模拟盘一样（不能超过 `LEVERAGE`）。第二条腿也受这个上限管。
- **按金额下单（零股）**：小金额也能按比例配仓。收盘后提交，下一个交易日开盘成交（和模拟盘一样）。小于 $5 的零碎订单不下。
- **单笔上限**：一笔订单不能超过“管理资金 × 杠杆上限 × 1.1”，超过就不下并报警（防程序或数据出错下超大单）。
  注意：一下子把金额或杠杆调低很多时，需要卖的那笔可能超过上限而不会自动下——这时分几次慢慢调低。
- 不做空（卖出永远不超过持有的股数）；不到 $5 的零头不去卖（免得券商拒单、天天报警）；订单唯一编号、结果不明不重试、STOP、单日亏 5% 只卖不买、坏数据不交易——和模拟盘相同。
- **不能用 `order.json` 手动下真钱单**（`trade.py place` 在实盘一律拒绝）。想手动交易真钱账户，请自己在 Alpaca 网页或手机 App 上操作。
- 实盘的成绩**不写进**和 ChatGPT 共享的成绩单（那边比的是模拟盘）。
- 每天换仓前的自检照常运行（永远在模拟模式 + 临时目录里跑，不碰任何真实账户）。

### 3. 记录在哪里
全部在 `live\` 子文件夹（和模拟盘分开）：`live\logs\paper_log.txt`（每天的运行记录）、`live\reports\paper_status.txt`（最新状态）、
`live\alerts.txt`（警报，开头带“【实盘】”）、`live\equity_history.csv` 和 `live\reports\scoreboard.txt`（成绩，附上模拟盘同一时期的成绩当对照）、
`live\logs\order_ledger.jsonl`（订单台账）、`live\logs\fills.csv`（成交价）、`live\STOP`（紧急停止）。
行情缓存 `data\` 两边共用（写入时先写临时文件再整体替换，前后脚运行也不会读到写了一半的文件）。
对账：`python tracking.py --root live --data data` → `live\reports\tracking.txt`。

### 4. 文件
| 文件 | 作用 |
|---|---|
| `set_live_keys.bat` | 输入**实盘**密钥（保存到 `.env.live`；不要发给任何人，也不要发给 Claude），并只读测试连接 → `live\connection_log.txt` |
| `live_dryrun.bat` | 实盘账户**空跑**：显示会怎么买卖，不下单 → `live\logs\live_dryrun_log.txt`、`live\reports\paper_status_dryrun.txt` |
| `live_status.bat` | 查看实盘账户、持仓、订单（只读）→ `live\orders\status.txt` |
| `enable_live.bat` / `disable_live.bat` | 打开（要输入 YES）/ 关闭真钱自动交易。关闭只是把开关文件改名成 `LIVE_ENABLED.off`，不删任何东西、不撤单 |
| `install_live_schedule.bat` / `uninstall_live_schedule.bat` | 安装 / 删除实盘的 2 个 Windows 计划任务（不动持仓和记录） |
| `run_live.bat` | 计划任务 **Noire Live Rotation**：周一至五 17:10（失败则 17:40、18:10 重试） |
| `run_live_monitor.bat` | 计划任务 **Noire Live Monitor**：周一至五 9:47–15:47 每小时，只读监控 |
| `emergency_stop_live.bat` | **实盘紧急停止**：停止自动交易 + 撤销未成交订单，**不卖持仓**（真钱，卖不卖由你决定） |
| `liquidate_live.bat` | 实盘**停下 + 全部卖出**：停止自动交易、撤单、市价卖出全部持仓（休市时下个交易日开盘成交），要输入 `SELL`；之后保持停止，恢复用 `resume_live.bat` |
| `resume_live.bat` | 解除实盘紧急停止（下一次 17:10 按信号继续） |

代码：`runmode.py`（模拟盘还是实盘，由环境变量 `NOIRE_PROFILE` 决定，只有实盘脚本才设成 `live`）、
`broker.py`（连接券商的唯一入口：三道闸 + 只读连接）、`paths.py`（实盘记录放 `live\`）。模拟盘脚本会主动清掉 `NOIRE_PROFILE`，永远是模拟盘。

### 5. 上线步骤（按顺序；第 6 步只有你本人能做）
1. 在 Alpaca 开实盘账户、打开两步验证（2FA）、入金（入金到账要几天）。
2. 在 Alpaca 网页切到实盘（Live）页面生成 API Key → 双击 `set_live_keys.bat` 粘贴。看到 `RESULT: OK` 就行。
3. 双击 `live_dryrun.bat`，看看它会怎么买（不下单）。
4. 决定金额和杠杆，告诉 Claude → Claude 改 `config.py` 的 `LIVE_MAX_CAPITAL`、`LIVE_MAX_LEVERAGE`、`LIVE_ENABLED`，跑测试、空跑给你看。
5. 双击 `install_live_schedule.bat`（装实盘的 2 个计划任务）。
6. 准备好了：**你自己**双击 `enable_live.bat`，输入 `YES`。当天 17:10 第一次真实下单，下一个交易日开盘成交。
7. 第二天看 `live\reports\paper_status.txt` 或日报。想停：`disable_live.bat`（不再下新单）/ `emergency_stop_live.bat`（再加撤单）/ `liquidate_live.bat`（停下并全部卖出）。

### 6. 上真钱前的检查清单（backlog #6；事实说明，不是投资、税务建议）
- [ ] **金额**：只放亏了也不影响生活的钱。到 11 月只能验证“程序在真账户上不出错”，几周的盈亏说明不了策略好坏（主要是运气和大盘方向）。
- [ ] **杠杆**（历史模拟 2000 年起，research_v4 H 节）：1 倍 → 每年约 10.2%、最大回撤约 -25%、最差一天约 -7%；
      最多 1.5 倍 → 12.3% / -31% / -8.5%；1~2 倍（和模拟盘一样）→ 13.6% / -37% / -11%。按自己能承受的回撤选。
- [ ] **保证金**：账户净值低于 $2,000 时券商不给借钱（只能 1 倍）；借钱利率约 6.5%/年，按每天收盘后的借款计息、每月扣一次。
      建议至少放 $2,000：低于 $2,000 时，换仓那晚“卖出还没成交的钱”不能先拿来买，买入要推迟一天（系统会自动补上）。
- [ ] **日内交易规则（PDT）**：系统每天只在开盘成交一次，同一只不会同一天又买又卖，不会被算成“日内交易”。
- [ ] **税**（如果在美国报税）：持有不到一年的盈利按普通收入税率；亏损卖出后 30 天内又买回同一只会触发 wash sale（亏损暂时不能抵税）；券商年初会发 1099。有疑问请问税务专业人士。
- [ ] **资金进出**：以后加钱或取钱，成绩单上的收益率会跳一下（还没有自动扣除出入金）。
- [ ] **账户里只放给 Noire 的钱**：不要在实盘账户里手动买这 8 只 ETF（自动换仓会把它们调回目标；监控会对“不是本系统下的订单/持仓”报警）。
- [ ] **最坏情况演练**：想好账户一天跌 7%、一个月跌 20% 时你会怎么做；知道 `emergency_stop_live.bat` 和 `liquidate_live.bat` 在哪；手机上装好 Alpaca App，出门时也能看和卖。
- [ ] **电脑**：17:10 要开着（睡眠可以，计划任务会唤醒电脑）。

**Claude 不会做的事**：替你输入或读取实盘密钥；替你运行 `enable_live.bat`、`run_live.bat`、`liquidate_live.bat`；自己下真钱订单；
没有你同意就改实盘的金额、杠杆或策略；削弱上面任何一道保护。

## 十六、记录更准确（2026-10-19，和实盘模式一起上线）

看了 10-19 第一天正式运行的数据后做的 4 处小改进（只改记录和报告，不改交易）：
1. **成绩单改记“收盘净值”**（backlog #10）：= 现金 + 持仓 × 当天官方收盘价。以前记的是 17:00 读到的券商净值，含盘后价格，
   和收盘净值差 -26 / -7 / +4 个基点（10-15 / 10-16 / 10-19），会盖住“实盘 vs 模型”对账里几个基点的真实差别。
   17:00 的券商净值另存在 `broker_equity` 列；行情不是最新或不完整的那天，仍用券商净值。（以前的几行没有改。）
2. **成绩单加一行“同场比较”**：只比所有系统都有记录的共同区间（Claude 和 ChatGPT 的起止日期不一样时，单看各自的收益不公平）。
3. **对账里的滑点改成按金额加权**（大单影响大），同时保留简单平均。10-19 第一批 3 笔：按金额加权 +10.5 个基点、简单平均 +8.9，合计约 $131，
   和研究假设的单边成本 0.10% 差不多（样本太少，等 1~2 个月再判断，backlog #5）。
4. **状态里的“最近已结束订单”显示成交时间（美东）**：以前显示的是券商的排队时间（UTC 08:00），看起来像早上 8 点下的单。
5. **（10-20 晚）状态页也用收盘净值**：`paper_status.txt` 的“账户净值”和“自起点”改成和成绩单同一个数（券商当时的读数写在旁边）。
6. **（10-20 晚）行情下载的一个漏洞**：晚上 8 点以后 Yahoo 有时把当天那一行给成空值（只有成交量）。以前这种行会写进缓存，
   还把 17:00 下载好的完整数据盖掉了（10-20 晚上空跑时发生过，第二天 17:00 会重新下载，不影响交易）。
   现在价格为空的行直接丢掉；如果新数据只是比本地缓存少了最新几天、其余都正常，就继续用本地缓存，不覆盖。
7. **（10-24）回撤统一用收盘净值**：以前 `equity_history.csv` 的 drawdown 列和 `risk_state.json` 的最高点用 17:00 券商读数，
   盘中监控每小时的读数也会抬高最高点，所以和成绩单/仪表盘对不上（10-22：4.80% vs 4.4%）。现在最高点 = `equity_history.csv`
   equity 列（收盘净值；10-19 及以前的老行就是当时的读数）的最大值；17:00 用收盘净值算回撤；盘中监控只拿当前读数和它比、不再改最高点。
   15% 报警门槛不变；回撤只用于记录和报警，不影响下单。已经写好的老行 drawdown 数字没有改。

## 十七、“偷看未来”陷阱测试（2026-10-22）

借鉴别人 BTC 策略作品集里提到的“还没做的陷阱测试”。新文件 `tests\test_lookahead.py`（8 项，跟每日自检一起跑，共 90 项）：
1. **做法**：造一份确定的假行情，把某一天之后的价格故意改乱（两个方向都试），再确认那天之前做出的决定一点都没变；变了 = 程序偷看了当时还不知道的价格。
2. **覆盖**：实盘的 `aplus.compute`（4 批信号 + 杠杆）、`dipbuy.positions`（第二条腿）；研究引擎里现在用的同一套算法（`research_v3.aplus_base`、`s1_rsi2`、`make_W`、趋势开关）；
   并核对同一份价格下研究和实盘算出的仓位完全一样。
3. **陷阱本身灵不灵**：故意写一个偷看明天价格的规则、以及“用当天开盘价算杠杆”的老写法，测试必须抓到。上线前又在代码里故意放了 7 处偷看，7 处全被抓到。
4. **查出的历史问题**：研究 v1、v2 用“开盘到开盘”的收益算杠杆，会用到当天开盘价（实盘前一天收盘就定了杠杆，看不到）。
   用真实数据重算 A+ 稳健版（1993–2026）：年化 13.1% → 13.2%，最大回撤 -39.3% → -40.0%，选 A+ 的结论不变。
   v3、v4、v5、expectations.py 和实盘都用收盘价，没有这个问题。旧报告没有改。
5. 10-22 17:50 提交前随每日自检运行：90 项全部通过（17:00 那次自检还没有这个文件）。

## 十八、网页仪表盘（2026-10-22）

手机、电脑都能打开的私人网页（claude.ai 上的“Noire 仪表盘”），分三页：
- **今天**：收盘净值、上线以来收益 vs SPY、回撤、实际杠杆、距追缴保证金；系统健康（换仓、自检、行情、监控、警报、杠杆、保证金、回撤）；当前持仓、第二条腿、四批信号。
- **成绩**：每天 Noire vs SPY 的累计涨跌、每天的杠杆、成绩单（含 ChatGPT 系统）、交易记录（参考价 vs 实际成交价）。
- **研究回测**：和实盘相同算法回放 2000 年至今（对数刻度净值、回撤、每年收益）。

数据来自新文件 `dashboard_export.py`：**只读**，把日志整理成几份 .json（`python dashboard_export.py [项目文件夹] [输出文件夹]`，
默认输出到 `reports\dashboard\`；加 `--backtest` 才重算研究回测）。它不连券商、不下单、不改任何记录，也不在你电脑上自动运行：
Claude 定时任务“Noire 仪表盘更新”（交易日 17:26）把需要的文件拷到云端、在云端运行它，再把结果上传到网页。
