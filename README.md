# Noire · 美股自动交易系统

> 原名 Excaliber，2026-10-15 改名为 Noire（法语“黑色”，取 “in the black” 盈利之意），以和 ChatGPT 的 Excalibur 区分。

目标路线：**回测 → 模拟盘 → 小资金实盘 → 加入 AI**。当前处于第 3 阶段（模拟盘）。

## 一、第一次运行（Windows）

1. 安装 Python 3.10 以上版本：https://www.python.org/downloads/ （安装时勾选 **Add Python to PATH**）
2. 打开命令提示符（Win+R → 输入 `cmd`），然后运行：
   ```
   cd /d D:\claude\Noire
   pip install -r requirements.txt
   python backtest.py
   ```
3. 结果会打印在屏幕上，图表和表格保存在 `reports\` 文件夹。

以后直接双击 `run_backtest.bat` 就能运行。

## 二、文件说明

| 文件 | 作用 |
|---|---|
| `config.py` | 所有参数：股票、日期、均线天数、手续费、止损 |
| `data.py` | 从 Yahoo Finance 下载日线数据，缓存到 `data\` |
| `strategy.py` | 策略（当前是 50/200 日双均线），想换策略就改这里 |
| `backtest.py` | 回测引擎：扣成本、次日开盘成交、止损、和买入持有对比 |

## 三、怎么看结果

- **年化收益**：每年平均赚多少
- **夏普比率**：每承担一份风险能换来多少收益，大于 1 算不错，小于 0.5 一般
- **最大回撤**：从最高点最多跌了多少，这个数决定你拿不拿得住
- **一定要和“买入持有”比**：跑不赢一直拿着 SPY 不动的策略，就没必要做

双均线策略在大牛市里通常跑不赢买入持有。它的价值在于大跌时（比如 2008、2022 年）把回撤压小，这是一个学习用的基准，不是赚钱秘籍。

## 八、工程加固（2026-10-15，借鉴 ChatGPT 版的做法）

- **订单唯一编号 + 台账**（`ledger.py`，`logs\order_ledger.jsonl`）：每笔订单编号 `noire-rot-日期-标的-方向`（手动单 `noire-man-...`）。

  **每天 17:00 换仓前自动先跑一遍（`preflight.py`），任何一项不通过当天就不交易并报警。**
- **git**：`setup_phase2.bat` 建立本地仓库；每天换仓前自动提交一次。密钥、数据、日志不进 git。
- **成绩单**（`scoreboard.py`）：每天 17:00 在 `equity_history.csv` 记一行净值，和同期 SPY 比较 → `reports\scoreboard.txt`。
  其他系统按同样格式（`date,equity` 两列的 CSV）放进 `scoreboard\` 文件夹就会一起比较。

## 九、有限次数自动重试（2026-10-15，借鉴 ChatGPT 版讨论）

`paper_job.py`：计划任务在 17:00、17:30、18:00 各运行一次。
- 今天已成功 → 直接跳过；另一次运行未结束（运行锁 <25 分钟）→ 跳过。
- 每次都先跑安全自检，换仓程序内部再核实台账、检查 STOP；订单编号固定，重试不会重复下单。
- 前两次失败只记日志；第 3 次仍失败才报警推送。
- 17:00 换仓的输出和 `reports\paper_status.txt` 增加“实际杠杆 / 距追缴保证金”。

## 十一、A+ 稳健版上线（2026-10-15，用户选定）

实盘规则（`aplus.py`，参数在 `config.py`；与 `research\research_v2.py` 的“A+ 稳健版”相同）：
1. **分 4 批换仓**：资金分 4 份，换仓日分别是每月最后一个交易日、以及它之前第 5、10、15 个交易日（用 Alpaca 交易日历算）。
   每批在自己的换仓日收盘后按 1/3/6/12 个月收益均值选前 2 名，持有到它的下一个换仓日。
2. **波动小的多买**：每批选中的两只按近 63 天日波动的倒数分配；分数 ≤0 的那一份换成 SHY。
3. **杠杆** = 30% ÷ 4 批合并后组合近 63 天的年化波动，限制在 1~2 倍；**SPY 收盘低于 200 日均线时最多 1 倍**。
4. **不借钱买现金**：杠杆只加在风险资产上，SHY 只用自有资金买。
5. 其余不变：收盘后提交市价单、次日开盘成交；相差不到总资产 5% 不动；单日亏 5% 只卖不买；STOP；订单唯一编号；Reg T 购买力上限。

历史模拟（2000 至今，5 种分批方式平均）：年化约 13.1%（按 Alpaca 真实借钱利息约 12.3%）、平均最大回撤约 -39%（最坏 -42%）；研究里核对过 738 个交易日的目标仓位，实盘程序和回测完全相同。（10-16 修正：之前写的 13.5% / -36% 只覆盖了 2 种分批方式，偏乐观。）
`paper_status.txt` 和换仓输出会列出 4 批各自的信号、合并后的权重、杠杆是怎么算出来的。

## 十三、第二条腿 + 对账工具（2026-10-16 用户同意启用；10-16 晚装上，10-19 周一 17:00 起生效）

**第二条腿：RSI(2) 超跌反弹**（`dipbuy.py`，参数在 `config.py` 的 `DIP_*`；规则和 `research\research_v3.py` 的 S1 相同，参数来自公开文献，没有调）：
1. **买**：SPY 收盘在 200 日均线上方（大趋势向上），而且 2 日 RSI < 10（最近两天跌得很急）。
2. **卖**：SPY 收盘高于 5 日均线（反弹了）。2000 年以来每年约 7~8 次，每次平均拿 3~4 天（最长 11 天），约 10% 的交易日有仓位。
3. **只用 A+ 没用完的额度**：第二条腿最多 = min(1 倍, 2 倍 − A+ 当天的风险资产仓位)，**总仓位永远不超过 2 倍**；
   A+ 已经用满 2 倍时就不加（历史上持有信号的日子里约一半是这样）。要用钱时先用 SHY 那部分自有资金，不够才借。
4. 和 A+ 在同一次 17:00 运行里算、一起下单（收盘出信号 → 次日开盘成交）；持仓状态每天由历史价格从头推算，不需要额外的状态文件。
5. 单日亏损超过 5% 那天照样只卖不买（第二条腿的买入会推迟到第二天，研究里没算这一点）。
6. 关掉：把 `config.py` 里的 `DIP_ENABLED` 改成 `False`（A+ 稳健版照常运行）。

上线前的核对（2026-10-16）：实盘程序和研究的买卖信号在 1993 年以来 8485 个交易日上完全一致；
2006 年以来第二条腿持有的 570 天里，实盘算出的“剩余额度”和研究完全相同（误差 < 1e-14）。
`paper_status.txt` 和换仓输出会多一行“第二条腿：未持有 / 持有中（哪天触发、用了多少额度）/ 卖出信号”；
`logs\targets.csv` 单独记录第二条腿占的仓位（`dip` 列），日报和周报据此分开记账。

**对账工具**：
- `fills.py`：`monitor.py` 每小时把本系统订单的实际成交价记到 `logs\fills.csv`（同一笔只记一次）。
- `tracking.py`：每天比较“账户实际赚的”和“完全按目标仓位、按开盘价成交应该赚的”，并算成交价比开盘价吃亏多少
  → `reports\tracking.txt`；第二条腿的贡献单独列出。只读，不连券商。

## 十四、程序加固 + 研究 v4（2026-10-16 凌晨，和第二条腿一起上线）

用户要求“再仔细钻研有什么可以改或优化的地方”。逐个文件检查后修了 6 处（都有新测试，共 56 项）：
1. **自检里的“定时炸弹”**：测试用的假行情以前是“随机走势画到今天”，每过一天就变一点。模拟发现从 **2027-02-12** 起测试会失败，
   而自检失败会让当天停止自动交易。现在假行情是固定的（每天形状完全一样），2030 年底以前每个工作日都验证过。
2. **券商明确拒单不再当成“结果不明”**（`ledger.py`）：例如购买力不足（HTTP 403）以前会触发“结果未知”警报并停下当晚其余订单；
   现在记为 REJECTED、报警说明原因、其余订单照常，第二天按最新仓位重新计算。超时、断线等真正不确定的情况仍然停下核实。
3. **买单不超过券商“现在”的购买力**（`paper_rotation.py`）：Alpaca 规定还没成交的卖单不算进购买力；超出的部分自动缩小，等卖单成交后下一次运行再补。
4. **卖出股数不超过持有股数**：券商市值和本地收盘价差得多时（例如盘后大涨），以前可能算出比持有更多的卖出股数 → 意外做空。现在封顶。
5. **坏数据保护**：任何一只最新价格缺失、≤0，或一天涨跌超过 25%（这几只 ETF 历史上从来没有过，多半是数据出错）→ 当天不交易；
   Yahoo 限流时同一次运行里自动再试两次（等 20 秒、60 秒）；新下载的数据明显不完整就不覆盖本地缓存；行情不是最新的会在状态和警报里提醒。
6. **其他**：监控以 `logs\paper_job_state.json` 判断上次换仓成败（重试成功不再误报“出错”）；成交记录“部分成交 + 全部成交”只算一次；
   休市日不记成绩单；重复编号被拒时向券商查一下并记进台账（避免误报“台账没有记录”）；
   空跑（不带 `--live`）的结果写到 `reports\paper_status_dryrun.txt`，不再覆盖正式的 `paper_status.txt`（日报、周报读的是正式的）。

**研究 v4**（`research\research_v4.py` → `research\report_v4.md`，结论在 `research\notes_v4.md`）：
试了 5 个有道理的改法（第二条腿扩展到 QQQ/IWM、第二条腿收盘成交、避险资产换 BIL、趋势开关加两种缓冲），**全部没达到事先定的标准，策略不改**。
另外：实盘执行规则比研究的理想执行每年只少约 0.1~0.2 个点；交易成本是最大的未知数（0.10% → 0.03% 每年多约 1.5 个点，等真实成交数据）；
压力测试：满仓 1.96 倍时单日暴跌 20% 账户会亏约 39%，要单日跌约 30% 才会被追缴保证金。

**研究 v5**（10-16 下午，`research\research_v5.py` → `research\report_v5.md`；数据：`research\fetch_long.bat` 下载标普 500 指数 1927 年起）：
- 第二条腿在 1950–1992 年（以前没用过的数据）勉强通过（每笔 +0.06%、胜率 62%），但 1960 年代是亏的 → 效应强弱随年代变化。
- 杠杆规则在历次大跌里只比 1 倍多跌约 1~10 个点，远好于固定 2 倍；1987-10-19 那天趋势开关已降到 1 倍（有运气成分）；没有一次被追缴。
- 极端风险：1929 年那样从 200 日线上方直接崩盘时，第二条腿会把总仓位补回 2 倍（近似：单日约 -26%）；试过“趋势开关也管第二条腿”，
  每年少约 0.8 点、平均回撤反而变大 → 不改，作为已知风险接受。
- `research\expectations.md` 已按“A+ 稳健版 + 第二条腿”重算（每年约 13.6%，回撤超过约 39% 算超出历史）。
